# V3: Review step, delta request, research-PR runs and holdout numbers

Read `AGENTS.md`, `docs/spec.md`, the ADRs and the descriptions of the V1 and V2 pull requests first.
One pull request against `main`.

## Goal

pecker-tap fits into the research loop: it checks the notes a research PR changed, pauses for David's
decision on every `contradicted` and `new_finding` entry, and only then writes a delta request for the
research bot. David's summary comes in German. Disagreements with Wren go to blind adjudication, and
the holdout set gives the first numbers that were never tuned on.

## Prerequisites (David, not the agent)

1. Wren's W48 pack and David's decisions on it as an overlay (for the holdout), under
   `private/packs/w48/`; Wren's raw copies for W48 if available.
2. The W48 notes at the research PR's merge commit (a local checkout at that SHA).

## Deliverables

1. **Selection by git range:** `--range <base>..<head>` selects the Markdown notes added or changed
   between two commits of the local checkout (read-only `git diff --name-only`, no checkout switch,
   no fetch). The run records both SHAs. Deleted notes are listed, not checked.
2. **Review step** (`graph/review.py`): after `write_pack` the graph interrupts (LangGraph
   `interrupt`) once per `contradicted` and `new_finding` entry. `tap review <run_id>` shows each item
   (claim, note lines, evidence, proposed correction, source) and takes David's answer: `yes`, `no`,
   `edit` (David's own wording or value) or `skip` (decide later). Answers resume the graph
   (`Command(resume=…)`); the SQLite checkpointer keeps a half-reviewed run for as long as it takes.
   Answers are stored in the run folder with a timestamp. Agent output never counts as David's
   answer: the review command reads from the terminal only, never from a file the run itself wrote.
3. **Delta request** (`delta.md`): only approved items (`yes`, `edit`), in the shape of Wren's delta
   requests: note path, line or section, old wording, new wording, source URL, one line on why.
   Conflicts stay conflicts (both values, no winner). Nothing is sent anywhere; David passes the file
   on.
4. **German summary** (`summary.md` in German, English kept as `summary.en.md`): counts per status,
   contradictions, new findings, unclear claims by reason, decision items, what David approved, cost.
   Wording plain and short; no claim text longer than the excerpt cap.
5. **Comparison and blind adjudication** (`tap compare`, `tap adjudicate`): `compare` lines up a run
   with a Wren pack for the same notes (by alignment as in V2) and lists agreements and
   disagreements. `adjudicate` presents each disagreement with both verdicts and their evidence in
   random order, labelled only "A" and "B", and records David's pick (`A`, `B`, `neither`, `skip`)
   with the mapping hidden until the session ends. The result is an overlay for the next gold
   version (ADR 0001); the current gold version stays frozen.
6. **Holdout evaluation:** `tap eval --gold holdout_w48_v1` refuses to run unless the prompts and
   thresholds (hashed into the run id) match a tagged release, so the holdout can't be used for
   tuning by accident. The report says so in its header.

## Acceptance checks

- [ ] Lint, format check, Pyright and tests pass; no network calls in tests.
- [ ] A fixture git repository (built by the test) with two commits: `--range` selects exactly the
      changed notes and records both SHAs.
- [ ] Review tests: interrupt per item; resume after a process restart; `skip` leaves the item open;
      `edit` lands in the delta; a run with no approved items writes no delta; review input from a
      non-terminal source is refused.
- [ ] Adjudication tests: random order per item, mapping hidden until the end, overlay written in
      the V2 format.
- [ ] The holdout guard refuses a run with changed prompts and accepts the tagged ones.
- [ ] First real loop, by David at the end: a research PR's range, review in the terminal, delta
      handed to the research bot; holdout numbers on `holdout_w48_v1`. Reports in `private/`; the PR
      gets the numbers David chooses to share.

## Out of scope

Attacking the verifier with pecker-drum, cross-note checks through Grove's MCP search (later
milestones). Running on a schedule. Any write to the notes repository or GitHub.
